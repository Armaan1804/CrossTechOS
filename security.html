Five Non-Negotiable System Invariants

The mathematical and cryptographic rules enforced at the database engine level that make financial fraud impossible.

INVARIANT 01

Immutability of Financial Records

The wallet_transactions table is strictly append-only. Custom PostgreSQL database triggers intercept and abort any UPDATE or DELETE operations. Adjustments must be recorded as explicit countervailing entries.

INVARIANT 02

Zero-Trust Multi-Tenancy (RLS)

Every query validates against the authenticated user's cryptographically signed GoTrue JWT claim (org_id). Database Row Level Security (RLS) guarantees complete tenant isolation even if application code is bypassed.

INVARIANT 03

Row-Locking ACID Consistency

Central wallet balance mutations strictly execute through process_wallet_transaction() utilizing SELECT ... FOR UPDATE row locks. This completely eliminates race conditions and double-spending across multiple job sites.

INVARIANT 04

Mandatory Client-Side WebP Transcoding

Raw high-resolution smartphone camera photos (5MB to 12MB) are transcoded in a background WebWorker to WebP (≤150KB) on the device prior to upload, preventing storage bloat and enabling instant sync over unstable 3G networks.

INVARIANT 05

Cloudflare R2 Zero-Egress Encryption

Receipts are stored with deterministic S3 keys (/receipts/{org_id}/{txn_id}.webp) on Cloudflare R2 with AES-256 server-side encryption and zero egress fees, guaranteeing no bandwidth penalty on statutory audits.
